# 접근성 점검 — KWCAG 2.2

한국형 웹 콘텐츠 접근성 지침 2.2의 33개 검사항목으로 이 사이트를 점검한 기록입니다. 첫 점검에서 미흡으로 나온 2건을 고친 뒤 같은 방법으로 다시 점검했습니다.

## 점검 기준

- **표준**: 한국형 웹 콘텐츠 접근성 지침 2.2 (KS X OT0003:2022). 표지에는 방송통신표준심의회, 2022년 12월 28일 개정으로 적혀 있습니다. 4개 원칙, 14개 지침, 33개 검사항목으로 구성됩니다(표준 표 1).
- **확인 방법**: 표준 원문 PDF(52쪽)를 직접 읽고 표 2~5의 검사항목 번호·이름과 각 항목 본문을 대조했습니다. 아래 결과표의 항목 번호와 이름은 원문 표에서 옮겼습니다.
- **판정 규칙**
  - 통과: 점검한 모든 페이지에서 요구사항을 충족함
  - 미흡: 한 곳이라도 충족하지 못함
  - 해당 없음: 항목이 다루는 콘텐츠(표, 동영상, 입력 서식 등)가 없음
- **미확인**
  - 원문 PDF는 웹에이전시 사이트(websoul.co.kr)에 게시된 사본입니다. 표준 배포처인 국립전파연구원(rra.go.kr)의 원본과 같은 판인지는 대조하지 못했습니다.
  - 한국지능정보사회진흥원 웹 접근성 사이트(wa.or.kr)는 점검 시점에 접속이 끊겨(연결 재설정) 그곳의 해설 자료와 대조하지 못했습니다.
  - 인증 심사 기관의 세부 판정 기준은 확인하지 않았습니다. 이 문서의 판정은 표준 본문을 기준으로 한 자체 판단입니다.
- **보조 점검**: 33개 검사항목 중 '확대 시 가로 스크롤(리플로)'과 'prefers-reduced-motion'을 직접 다루는 항목은 없습니다(원문 확인). 그래서 이 둘은 결과표와 별도로 기록했습니다. 참고로 앞의 것은 WCAG 2.1의 1.4.10 리플로에 해당합니다. 뒤의 것은 WCAG 2.1의 2.3.3 상호작용 애니메이션(AAA)과, KWCAG 6.2.2 정지 기능 제공에 가깝습니다.

## 도구와 방법

| 도구 | 버전 | 용도 |
| --- | --- | --- |
| axe-core | 4.14.0 | 자동 점검. 태그 `wcag2a` `wcag2aa` `wcag21a` `wcag21aa` `wcag22aa` `best-practice` |
| Chrome (headless) | 155.0.8059.84 | 점검 브라우저 |
| playwright-core | 1.64.1 | 브라우저 조작(화면 크기, 키보드 입력, 움직임 줄이기 설정 흉내) |
| html-validate | 9.7.1 | 마크업 문법 검사(`html-validate:standard` 프리셋) |
| 자체 Node 스크립트 | — | 아래 수동 점검 보조 |

- **자동 점검**: 페이지마다 데스크톱(1440×900)과 모바일(375×812) 두 화면에서 axe를 돌렸습니다. 스크롤로 나타나는 요소가 보이도록 페이지 끝까지 한 번 스크롤한 뒤 실행했습니다.
- **수동 점검을 돕는 스크립트**(저장소에는 넣지 않음)
  - Tab 키만 눌러 초점이 가는 순서를 기록하고, 숨은 요소나 화면 밖으로 초점이 가는지 확인했습니다.
  - 초점이 있을 때와 뺐을 때 화면을 비교해 초점 표시가 보이는지 쟀습니다. 차이가 거의 없는 곳은 캡처를 직접 확인했습니다.
  - 320px(1280px 화면을 400% 확대한 너비)와 640px(200%)에서 가로 스크롤이 생기는지 확인했습니다.
  - 375px에서 링크·버튼 크기를 재서 표준이 권하는 대각선 6.0mm(약 22.7 CSS px) 미만인 것을 찾았습니다. 상자가 작으면 실제로 눌리는 범위를 `elementFromPoint`로 다시 쟀습니다(재점검 때 추가한 방법).
  - 움직임 줄이기(`prefers-reduced-motion: reduce`) 설정을 켠 화면과 끈 화면의 애니메이션을 비교했습니다.
  - axe가 판단하지 못한 명도 대비(사진·반투명 배경 위 글자)는 화면 캡처로 다시 쟀습니다. 글자를 투명하게 만든 화면과 원래 화면을 비교해 글자 획 아래 배경 픽셀만 고르고, 하위 5% 대비값으로 판정했습니다.
- **재점검**: 수정 뒤 위 도구와 스크립트를 그대로 다시 돌렸습니다. 저장소의 스모크 테스트(`npm test`, 17개)도 모두 통과했습니다.
- **하지 않은 것**: 스크린리더(NVDA, 센스리더, VoiceOver) 실사용, 실제 모바일 기기, 브라우저 확대 기능 자체(320px 화면으로 대신함), 고대비 모드.
